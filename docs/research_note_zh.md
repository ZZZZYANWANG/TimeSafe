# TimeSafe v0.2：量化研究中的时间合法性审计

量化研究中最危险的未来信息，往往不是显式的 `shift(-1)`，而是全样本标准化、全样本 PCA、双向滤波、事后连续合约、未来回填，以及尚未成熟的标签进入训练。TimeSafe 将这些假设转换为可执行测试。

对于纯函数式因子，TimeSafe比较：

\[
F(D_{1:t}) \stackrel{?}{=} F(D_{1:T})_t.
\]

若未来数据加入后过去输出改变，则该实现不满足前缀不变性。v0.2明确区分全量和抽样证据：只有检查全部合格历史时点且存在可比较输出时，才会给出 `PASS`；抽样无异常为 `WARN`，零输出为 `INCONCLUSIVE`。

对于模型、PCA、Scaler等可训练状态，单纯的黑盒函数测试可能漏掉预先拟合的外部对象。v0.2新增重拟合审计：每个历史检查点创建两个全新模型实例，分别对历史前缀和完整输入运行同一训练代码。训练代码若错误使用未来行，两次历史预测将出现差异。scikit-learn模型通过官方 `clone` 机制生成新实例，不自行实现模型复制。

标签合同进一步扩展到盘内事件：

```text
pre_open < open < intraday < close < after_close
```

因此，“收盘后决策、当天开盘成交”等不可能时序会直接被拒绝。安全间隔不再只写在报告中，而是实际进入训练掩码；严格过去式 walk-forward 不再接受无意义的 embargo 参数，而任意训练测试集合可以通过专门接口执行 purge、safety gap 和 post-test embargo。

TimeSafe仍不判断策略是否过拟合、机制是否真实、交易成本是否合理。它解决的是更前置的问题：**这个历史结果是否在时间上有资格被评价。**
