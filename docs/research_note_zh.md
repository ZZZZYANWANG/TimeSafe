# 回测中最危险的未来函数，往往没有写在代码里

量化研究中的未来信息并不总以 `shift(-1)` 的形式出现。更常见也更隐蔽的情况是：研究者在完整历史上估计均值、标准差、主成分、聚类边界、异常值阈值或缺失值填充规则，然后把这些结果回填到过去。代码表面上没有引用“未来价格”，但过去的因子值实际上已经由未来样本参与决定。

TimeSafe使用一个简单但严格的动态原则进行检查。设 `D[1:t]` 是历史时点 `t` 真正能够看到的数据，`F` 是任意因子、特征工程或模型管线。若该管线具有合法的时间因果性，则应满足：

\[
F(D_{1:t}) = F(D_{1:T})_t.
\]

换言之，只给模型截至当时的数据计算一次，再给它完整历史并回看同一个过去时点，两次输出应当一致。若加入未来数据后过去的信号发生变化，就说明实现中存在全样本拟合、双向窗口、未来回填、事后分类或其他未来依赖。

这一方法与静态代码扫描互补。静态扫描可以发现明显的负向位移和居中窗口，但很难覆盖隐藏在第三方函数、模型状态和复杂预处理中的泄漏。TimeSafe把管线视为黑盒，直接检验它的历史输出是否稳定，并可通过命名阶段定位第一个发生变化的处理环节。

时间合法性还包括标签是否成熟。若信号在 `t` 日收盘后形成、`t+1` 日开盘执行，并用 `t+20` 日收盘计算收益，那么靠近训练边界的样本在当时并不知道自己的完整标签。TimeSafe根据决策、执行、持有期和发布滞后推导标签区间，并检查训练标签与测试区间是否重叠，从而给出最小purge要求。

TimeSafe并不声称一次通过就能证明整个研究无误。若数据供应商已经用修订后的数据覆盖历史版本，前缀数据本身也可能被污染；成交、成本、容量、参数搜索过拟合和经济机制验证也需要其他工具完成。它解决的是更基础的问题：**在评价一个回测之前，先确认历史信号没有被未来数据重写，训练标签在当时确实已经可见。**
